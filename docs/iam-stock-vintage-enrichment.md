# IAM preprocessing to premise to TRAILS: validation boundary

This work adds an upstream flodym-backed reconstruction feature to
`iam-preprocessor` and exact annual accessors to premise. TRAILS consumes the
existing version-1 stock-vintage resource; its runtime source is unchanged.
The initial scope is one scenario, **REMIND SSP2-NPi2025**, with four asset groups
and a reviewed 2022–2050 horizon.

## What the new route establishes

Existing IAM stock, sales/additions, service and applicable lifetime variables
are combined with explicit initial composition and survival assumptions. The
preprocessor exports stock and service shares separately, with conditional
initial survival, balance diagnostics, sensitivity cases and hashed provenance.
The paired premise runtime reader selects exact region/year profiles, verifies
the source/report relation and passes them to the existing explicit inventory
binding/export contract. flodym is not needed in either runtime consumer.

`dev/stock_vintage/check_iam_enrichment.py` checks two packages generated by the
actual premise exporter from actual enriched REMIND profiles. One fixture has
constant synthetic biosphere intensities and one changes them between inventory
anchors. Both use simple synthetic inventories with the documented pilot
service/capital units and coefficients. They are interface tests, not regional
ecoinvent LCA results or new empirical validations.

For each of four assets, the checker runs both signs (+1, -2) at 2050, 2023, 2030
and repeated 2023. It independently checks:

- every pulse against the prepared cohort weights;
- total signed demand against the unchanged inventory coefficient;
- physical dates against the graph, including dates before the inventory range;
- signed LCI against an analytical weighted sum of the fixture's background
  factors, interpolated/clamped only for inventory lookup;
- failure on an absent service year rather than use of the nearest profile.

This is 64 signed routing/LCI cases across the two packages. Existing stock,
lifecycle, cache and adaptive tests continue to cover TRAILS' implementation.
The earlier five licensed full-inventory pilots and their private archive are
preserved. This change does not replace those packages, promote global defaults,
or claim that parent cohorts determine component replacement/disposal calendars.

## Reproduction

1. Use `iam-preprocessor`'s `examples/run_remind_stock_pilot.py` with the existing
   private evidence archive. Generate the enriched file and report locally.
2. Preserve the bytes under a premise-compatible scenario filename. Run the
   premise branch's `dev/stock_vintage/export_iam_enrichment_fixture.py`.
3. In this checkout, run:

```console
python dev/stock_vintage/check_iam_enrichment.py /path/to/integration-output
```

The checker writes `trails-validation.json` next to each fixture. Package hashes
are verified before loading. Generated scenario data, reports and figures stay
local under their original source rights.

## Remaining scientific limits

These are labelled reconstructions. The UK vehicle and WECC plant observations
are composition proxies for EUR/USA. Lifetime means/shapes, future utilization,
new-cohort exposure and additional exits remain assumptions. Equal service
gives equal stock/service shares only under that explicit convention. Common
amortisation and original exchange amounts remain unchanged.

Published stock levels and independently annualized inflows can conflict; the
producer reports that disagreement instead of inventing balancing flows. Exact
REMIND vintages, exact-run reporting identity, held-out empirical validation,
selective exits and a reviewed post-2050 reporting-period mapping are not claimed.
The existing water pilot remains an external-data constant-stock reconstruction.

The complete configuration/method contract and one-scenario data-gap strategy
are maintained in the preprocessor repository's `docs/stock-vintages.md` and
`docs/stock-vintage-validation.md`. The runtime API is documented in premise's
`docs/development/stock-asset-temporal/iam-enrichment.md`.
